A statement becomes
a consistent review request.

Three source stops connect the actual kernel. The public demo uses synthetic or de-identified data; findings are review candidates, not confirmed violations.

Stop 1 · Establish trustworthy input

src/lib/gemini.ts extracts structured fields, and src/lib/validation.ts checks runtime facts, quantities and total reconciliation. Missing codes and dates remain unknown. The actual route is src/app/api/audit/route.ts.

Open: extraction · validation. Synthetic examples call the same engine without document AI.

Stop 2 · Reconcile the user's selection once

src/lib/rules-engine.ts owns itemReviewAmount, recalculateReport and the deterministic package compiler. src/lib/store.ts changes the selection and saves the regenerated report. The UI does not patch letter strings or independently recalculate a second report.

Open: domain calculation · selection action.

Stop 3 · Display the exact report and its package

src/hooks/use-report.ts resolves exact local/sample/shared IDs after encrypted hydration. src/app/results/[id]/page.tsx and src/app/dispute/[id]/page.tsx consume the same report. Unknown or revoked links show an error; they do not become samples.

Open: loader · report · package.

A project-grounded practice to reuse

The audit found that deselecting a charge changed the dashboard while leaving the letter stale. The regression now selects one authority for the amount and regenerates every representation.

  1. Run npm test. Find the named test reconciles each selected item once across package, closing and phone guide in tests/release.test.ts.
  2. Trace one synthetic toggle through the store into recalculateReport, then the report and letter pages.
  3. Reuse the practice on another app: identify one fact shown in several places, make its calculation authoritative, and test the user's action across the representations.

This is an offered technical learning activity. The document does not claim the contributor completed a personal exercise or reflection.
